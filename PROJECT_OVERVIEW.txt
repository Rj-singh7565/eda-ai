           AI-BASED EDA ASSISTANT — OVERVIEW & TECHNICAL SPECIFICATION
================================================================================

1. PROJECT OVERVIEW & PURPOSE
-----------------------------
The AI-Based EDA (Exploratory Data Analysis) Assistant is an enterprise-grade, 
decoupled Retrieval-Augmented Generation (RAG) system built to analyze organizational 
reports, financial statements, annual filings, placement statistics, presentations, 
spreadsheets, and other data-heavy documents across 10+ file formats.

The system features a decoupled architecture with a FastAPI Python backend service 
and a modern Next.js / React TypeScript split-pane frontend workspace. Users can upload 
documents (individually or in bulk via ZIP archives), switch between documents in an 
interactive sidebar, inspect normalized Markdown views, submit natural-language 
queries, and receive real-time streaming answers with page/slide/row citations.


2. KEY FEATURES & DECOUPLED ARCHITECTURE
----------------------------------------
- Decoupled Next.js / React Frontend: Modular split-pane UI built with Next.js 14, 
  React 18, and TypeScript. Features dark/light themes via CSS custom properties, 
  drag-and-drop file ingestion zone, real-time stage progress bars, Markdown viewer, 
  and citation drawer.
- Modular FastAPI Backend: Scalable backend organized into clear domain layers:
  * API Routes (`backend/app/routes/`): `upload`, `documents`, `chat`, `health`
  * Core Services (`backend/app/services/`): `extraction`, `normalization`, `chunking`, 
    `embeddings`, `vector_store`, `llm`, `retrieval`, `ingestion`, `storage`
  * Database Layer (`backend/app/database/`): SQLite engine with safe schema migrations
- Root Compatibility Layer: Root wrapper files (`app.py`, `ingestion.py`, `retrieval.py`, 
  `database.py`, `rag.py`, `config.py`) delegate directly to `backend/app/` to maintain 
  full backward compatibility for `uvicorn app:app` and Pytest execution.
- Multi-Format Ingestion: Deep text & table extraction for PDF, DOCX, PPTX, XLSX, CSV, 
  TXT, Markdown (.md), and Images (PNG/JPG/JPEG/BMP/TIFF via Tesseract OCR).
- ZIP Batch Processing: Drag-and-drop .zip archives (up to 15 files). Archive contents 
  are unpacked, format-validated via binary magic bytes, and ingested in background tasks.
- Binary Magic Byte Detection: File payloads are verified using binary header inspection 
  before extension fallbacks to prevent malicious or corrupted file processing.
- Pinecone Namespace Isolation: Embeddings and metadata are strictly isolated per 
  document using Pinecone namespaces (`namespace=doc_id`).
- Canonical Markdown Normalization: Standardizes extracted data into clean Markdown 
  with structured YAML front matter persisted to `processed/{doc_id}.md`.
- Sentence-Aware Chunking: Headings-aware Markdown chunking that preserves tables 
  intact as dedicated table chunks while splitting narrative text by paragraph/sentence 
  boundaries (~600 chars, 80 overlap).
- Similarity Threshold Filtering: Filters out low-confidence vector matches 
  (score < 0.35) to mitigate LLM hallucinations.
- Token-by-Token SSE Streaming: Real-time Server-Sent Events (SSE) streaming powered 
  by Groq's Meta Llama 3.3 70B model.
- Conversational Session Memory: Retains recent Q&A turns per document for context-aware 
  follow-up conversations.
- Optimistic UI Document Deletion: Instant client-side sidebar removal (<10ms) while 
  backend handles DB deletion and offloads filesystem and Pinecone cleanup to background 
  threads. Polling race condition guards prevent deleted docs from re-appearing.
- Rate Limiting & Resilience: Integrated rate limiting via `slowapi` and exponential 
  backoff retries using `tenacity`.

5. STEP-BY-STEP WORKING MECHANISM
----------------------------------

[ PHASE 1: DOCUMENT UPLOAD & VALIDATION ]
1. File Upload (/upload):
   - Drag-and-drop or select file(s) via the frontend UploadZone component.
   - Backend checks file size (<= 25MB) and executes binary magic byte inspection 
     (`storage.py` / `ingestion.py`).
   - For `.zip` archives: entries are extracted, format-validated, registered with 
     their own `doc_id`, and dispatched to independent background ingestion tasks.

[ PHASE 2: DOCUMENT INGESTION PIPELINE ]
2. Extractor Dispatch & Markdown Normalization (`extraction.py`, `normalization.py`):
   - Extractor parses raw structure into uniform page/slide/row text blocks and tables.
   - Normalizer constructs canonical Markdown file with YAML front matter metadata.
   - Normalized Markdown saved to `processed/{doc_id}.md`.

3. Sentence-Aware Chunking & Embedding (`chunking.py`, `embeddings.py`, `vector_store.py`):
   - Markdown structure is chunked preserving tables intact as table blocks.
   - `bge-small-en-v1.5` model generates 384-dimensional embeddings for each chunk.
   - Vectors upserted to Pinecone under `namespace=doc_id`.
   - Ingestion status updated in SQLite: `parsing` → `chunking` → `embedding` → `indexing` → `ready`.

[ PHASE 3: RAG RETRIEVAL & STREAMING ]
4. Query Retrieval & Similarity Threshold (`retrieval.py`):
   - User query embedded and queried against Pinecone `namespace=doc_id`.
   - Results scored below 0.35 similarity threshold are discarded.

5. SSE Answer Streaming & Citation Drawer (`llm.py`, `ChatWindow.tsx`):
   - Recent conversation turns (up to 4) retrieved from SQLite `chat_history`.
   - Groq API streams answer tokens over SSE to Next.js frontend.
   - Interactive citation chips rendered; clicking opens citation drawer showing exact source context and score.

[ PHASE 4: DOCUMENT MANAGEMENT & POLICIES ]
6. Optimistic Document Deletion (`documents.py`, `DocumentSidebar.tsx`):
   - Frontend removes document immediately from sidebar state (<10ms).
   - Backend deletes SQLite records (<1ms) and delegates file/Pinecone cleanup to background tasks.
   - Polling guards prevent race conditions.

8. HOW TO RUN THE PROJECT
-------------------------
Option A: Local Development (Decoupled Frontend + Backend)
1. Configure Environment:
   Ensure `.env` contains:
   GROQ_API_KEY=your_groq_api_key
   PINECONE_API_KEY=your_pinecone_api_key
   PINECONE_INDEX_NAME=eda-assistant

2. Start FastAPI Backend:
   python -m venv venv
   venv\Scripts\activate          (Windows)
   pip install -r requirements.txt
   .\venv\Scripts\uvicorn.exe app:app --reload --port 8000


3. Start Next.js Frontend:
   cd frontend
   npm install
   npm run dev

4. Access Application:
   Open http://localhost:3000 (Frontend) or http://localhost:8000 (Backend API docs at /docs)

Option B: Docker Compose
1. Ensure `.env` is configured.
2. Run: docker-compose up --build
3. Open browser: http://localhost:8000

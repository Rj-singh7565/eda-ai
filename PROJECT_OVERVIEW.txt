1. EXECUTIVE SUMMARY & PROJECT PURPOSE
--------------------------------------
• Purpose: Enterprise RAG (Retrieval-Augmented Generation) document intelligence system.
• Core Goal: Analyze complex, multi-format organizational documents (financial reports, 
  placement stats, annual filings, spreadsheets, presentations, and OCR images).
• Key Interface Feature: Swapped workspace layout positioning the AI Chat input controls 
  at the top and displaying clean, data-driven table answers in the main workspace pane below.
• Output Guarantee: Strict Markdown/HTML table output with complete sanitization of internal 
  metadata bracket labels (such as `[Sheet 'Data' (Rows 1-39) Table]`).


2. KEY FEATURES & CAPABILITIES
------------------------------
• Swapped AI Chat & Answer Layout:
  - Top AI Chat Input Bar: Query textarea & suggested analytical chips placed at top.
  - Main Answer Workspace: Renders clean table outputs directly below the prompt bar.

• Strict Table Output & Data Cleanliness:
  - Exclusive Table Response: Prompts LLM to return strictly Markdown tables.
  - Zero Internal Noise: Filters out chunk headers, sheet names, and raw metadata.

• Decoupled Architecture:
  - Python FastAPI Backend: High-performance REST & SSE streaming server.
  - Next.js 14 Frontend: Split-pane React workspace with dark/light themes.
  - Root Compatibility Layer: Enables direct backward-compatible execution (`app.py`).

• Multi-Format Ingestion Engine:
  - 10+ File Extensions Supported: PDF, DOCX, PPTX, XLSX, CSV, TXT, MD, PNG, JPG, ZIP.
  - Binary Magic Byte Inspector: Verifies file headers to detect format spoofing.
  - ZIP Batch Extractor: Unpacks and processes up to 15 documents concurrently.

• Enterprise Vector Search & RAG Pipeline:
  - Canonical Markdown Normalization: Standardizes parsed documents into structured Markdown.
  - Sentence & Table-Aware Chunking: Preserves data tables intact during chunking (~600 chars).
  - Pinecone Vector Storage: Namespaced per document (`namespace=doc_id`) with score filtering (>0.35).
  - Groq Llama 3.3 70B Streaming: Real-time token streaming via Server-Sent Events (SSE).

5. STEP-BY-STEP WORKING MECHANISM
----------------------------------
• Step 1: Upload & Format Validation
  - User submits file or ZIP archive via frontend UploadZone.
  - Backend verifies binary magic bytes and file size limit (<= 25MB).

• Step 2: Extraction & Markdown Normalization
  - Format-specific extractor converts raw file into structured text blocks and tables.
  - Normalizer builds canonical Markdown file with YAML metadata at `processed/{doc_id}.md`.

• Step 3: Chunking, Embedding & Vector Upsert
  - Markdown text is chunked using sentence-aware splitting (~600 chars, 80 overlap).
  - Tables are kept intact as single chunk units.
  - `bge-small-en-v1.5` generates 384-d vectors, upserted to Pinecone under `namespace=doc_id`.

• Step 4: RAG Retrieval & Similarity Guard
  - User query is embedded and searched against Pinecone index.
  - Low-confidence matches (<0.35 similarity score) are automatically filtered out.

• Step 5: Clean SSE Answer Streaming & Table Rendering
  - Excerpts are sanitized of internal `[Sheet ...]`, `[Page ...]` tags before LLM prompt assembly.
  - Groq API streams answer strictly as a Markdown table.
  - Frontend renders responsive HTML `<table>` elements with styled headers and borders.


6. FILE & DIRECTORY STRUCTURE
------------------------------
• `backend/app/`           - Core FastAPI application package
  - `main.py`              - App initialization, CORS, middleware, router mounts
  - `config.py`            - System settings, environment variables, paths
  - `database/`            - SQLite connection manager, schema models, migrations
  - `routes/`              - Endpoint modules (`upload.py`, `documents.py`, `chat.py`, `health.py`)
  - `services/`            - Extraction, chunking, embeddings, vector store, LLM & retrieval

• `frontend/`              - Next.js 14 TypeScript web client
  - `app/`                 - Next.js App Router (`page.tsx`, `layout.tsx`, `globals.css`)
  - `components/`          - Modular UI (`DocumentSidebar.tsx`, `ChatWindow.tsx`, `ChatMessage.tsx`, `ChatInput.tsx`)
  - `lib/`                 - API client (`api.ts`), type declarations (`types.ts`)

• `templates/` & `static/` - Root HTML/CSS/JS interface (`index.html`, `script.js`, `style.css`)
• `app.py`                 - Root wrapper entrypoint for backend execution
• `tests/`                - Pytest suite (`test_pipeline.py`, `test_multi_format.py`, `test_normalization.py`)

8. HOW TO RUN THE PROJECT & LIVE PORT STATUS
---------------------------------------------
• Active Server Status:
  - Backend Server: RUNNING on http://localhost:8000 (Python app.py via Uvicorn)
  - Frontend Workspace: RUNNING on http://localhost:3000 (Next.js Dev Server)

• Execution Commands:
  - Run Both Servers Concurrently:
    npm run dev

  - Run FastAPI Backend Independently:
    venv\Scripts\python.exe app.py

  - Run Next.js Frontend Independently:
    cd frontend
    npm run dev

  - Run Automated Pytest Suite:
    venv\Scripts\python.exe -m pytest

• Application Access URLs:
  - Next.js Workspace: http://localhost:3000
  - FastAPI Backend / Swagger Docs: http://localhost:8000/docs

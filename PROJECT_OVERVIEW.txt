1. EXECUTIVE SUMMARY & CORE MISSION
================================================================================
• Purpose:
  AI-Based EDA Assistant is an enterprise-grade Exploratory Data Analysis (EDA)
  and Document Intelligence platform combining Retrieval-Augmented Generation
  (RAG) with a deterministic DataFrame computation engine.

• Dual-Engine Architecture:
  1. Deterministic Tabular Analytics Engine (CSV & Excel):
     Executes verified, schema-aware Pandas/NumPy operations guaranteeing 100%
     column preservation, mathematical accuracy, and zero LLM hallucinations
     on numerical aggregations, filtering, group-bys, and metrics.
  2. Adaptive Document RAG Engine (PDF, Word, PPTX, Plaintext, OCR Images):
     Performs semantic vector search over localized coordinate chunks (Page,
     Slide, Row, Paragraph markers) with Pinecone namespace isolation and
     token-by-token SSE streaming via Groq API models.

• User Experience & Workspace Design:
  - Full Analytics Dashboard: Master Overview with real-time KPI metrics,
    storage allocation, data quality health scores, and live activity feeds.
  - Dedicated Dataset Library: Complete catalog with document status tracking,
    ingestion metrics, normalized Markdown inspection, and instant deletion.
  - Focused Analysis Workspace: Ultra-clean 64px compact navigation rail,
    header dataset switcher, 5 analytical prompt chips, multi-turn Turn Cards
    with Table / Chart / SQL view toggles, latency counters, and AI insights.
  - Sub-Document Evidence Reader: Deep-linked citations with coordinate markers,
    side drawer evidence panel, and synchronized Markdown source reader.
  - Multi-Format Export Engine: 1-click export of analysis turns to Markdown,
    CSV, JSON, PNG, or PDF report formats.

• Deployment & Cloud Scalability:
  - Backend: FastAPI deployed via Docker container on Render / Railway.
  - Frontend: Next.js 14 App Router deployed on Vercel.
  - Dual Persistence: PostgreSQL (Supabase / Neon) for cloud production with
    automatic schema migrations; zero-config SQLite3 for local development.
  - Pluggable Storage: AWS S3 / Supabase Object Storage with local fallback.

2. KEY CAPABILITIES & SYSTEM HIGHLIGHTS
================================================================================
• Hybrid Query Routing & Planning (`query_router.py`):
  - Automatically classifies queries into 'STRUCTURED_DATA_OPERATION',
    'DOCUMENT_RAG', or 'HYBRID'.
  - Heuristic and schema-aware intent parsing: detects comparison operators,
    mathematical keywords, aggregation verbs, and active column headers.
  - Generates deterministic DataFrame operation plans without relying on
    unpredictable code generation.

• Safe Deterministic DataFrame Engine (`dataset_engine.py`):
  - In-memory DataFrame cache with file modification timestamp (`mtime`) validation.
  - Implements operations: select, filter, sort_by, group_by, aggregations,
    statistics (mean, median, std, min, max, count, missing).
  - Guarantees 100% column preservation on select/filter commands.
  - Produces pristine GitHub-flavored Markdown tables and feeds compact
    context to Groq LLMs for concise 1-2 sentence executive insights.

• Multi-Format Document Ingestion Engine (`ingestion.py`, `extraction.py`):
  - Supports 10+ file formats: PDF, DOCX, PPTX, XLSX, CSV, TXT, MD, PNG, JPG,
    JPEG, and ZIP archives.
  - Binary Magic-Byte Inspector: Reads binary file headers (`%PDF-`, `PK\x03\x04`,
    `\xFF\xD8\xFF`, etc.) to reject disguised or malicious file extensions.
  - Resilient ZIP Batch Unpacker: Validates against Zip-Slip path traversals,
    enforces 150MB decompression limits, streams writes to disk in 64KB chunks,
    and isolates per-file failures so healthy files process successfully.

• Unified Coordinate Markdown Normalization (`normalization.py`, `chunking.py`):
  - Standardizes all parsed inputs into canonical Markdown with coordinate comments
    (`<!-- coordinate: page=1 -->`, `<!-- coordinate: slide=3 -->`, etc.).
  - Preserves tabular structures intact during chunking (~600 chars, 100 overlap).
  - Saves normalized artifacts with YAML metadata to `processed/{doc_id}.md`.

• Local Vector Embeddings & Isolated Retrieval (`embeddings.py`, `retrieval.py`):
  - Dense 384-dimensional embeddings generated locally via `BAAI/bge-small-en-v1.5`.
  - Zero external embedding API cost or rate limits.
  - Thread-safe model access with internal lock and CPU thread count tuning.
  - Pinecone Serverless Index with document-level namespace isolation (`namespace=doc_id`).
  - Score threshold filtering (>0.35) and multi-tier retrieval fallback to
    lexical Markdown scanning if vector indexes are unavailable.

• High-Speed SSE Streaming & Model Fallback Chain (`llm.py`):
  - Token-by-token streaming over Server-Sent Events (SSE) via Groq API.
  - Multi-candidate resilience chain: Meta Llama 3.3 70B Versatile, GPT-OSS 120b,
    GPT-OSS 20b, Qwen 3.8 27b, Llama 3.1 8b, and Mixtral 8x7b.
  - Automatic filtering of internal `<think>...</think>` reasoning tokens.
  - Multi-turn conversation memory retaining recent Q&A turns per document.

5. END-TO-END DATA PROCESSING WORKFLOW
================================================================================
• Stage 1: Upload & Streaming Ingestion
  - User submits file or ZIP archive via Drag-and-Drop Dropzone or File Picker.
  - Endpoint (`POST /upload` or `POST /api/documents/upload`) streams file to disk
    in 64KB chunks to eliminate RAM duplication.
  - Binary magic-byte detector checks header signatures.
  - If ZIP: unpacks with Zip-Slip path validation and dispatches per-file background tasks.

• Stage 2: Extraction & Coordinate Normalization
  - Format-specific extractor transforms raw file into clean text blocks & tables.
  - Normalizer builds canonical Markdown with YAML frontmatter and coordinate tags.
  - Normalized document is saved to `processed/{doc_id}.md` (or cloud storage).

• Stage 3: Coordinate-Aware Chunking & Embedding
  - Document text is split into semantic chunks (~600 chars, 100 char overlap).
  - Data tables are kept intact as dedicated tabular chunk units.
  - `BAAI/bge-small-en-v1.5` embeds text into dense 384-dimensional vectors.
  - Vectors are upserted to Pinecone under `namespace=doc_id` in 200-vector batches.
  - Document status transitions from `processing` to `ready`.

• Stage 4: Query Routing & Intent Classification
  - User submits analytical question via CommandBar or quick prompt chip.
  - `query_router.py` inspects question against active dataset schema.
  - Route A: Structured Dataset Operation (CSV/Excel with tabular intent).
  - Route B: Document RAG Retrieval (PDF, Word, PPTX, or general questions).

• Stage 5: Execution & SSE Response Streaming
  - Route A (Structured): `dataset_engine.py` executes Pandas operations, builds
    pristine Markdown table, creates exact citation, and streams table + AI insight.
  - Route B (Document RAG): Vector search retrieves top-5 chunks (score > 0.35),
    sanitizes internal bracket noise, constructs grounded prompt with chat history,
    and streams tokens via Groq API.
  - Turn card is updated with response, latency timer, citation chips, and view toggles.
  - Q&A turn is persisted to database (`chat_history` table).

9. EXECUTION, LOCAL DEVELOPMENT & DEPLOYMENT RUNBOOK
================================================================================
• Local Development Quick Start:
  1. Prerequisites:
     - Python 3.12+ installed
     - Node.js 18+ and npm installed
     - Tesseract OCR (optional, for image OCR)

  2. Install Backend & Frontend Dependencies:
     pip install -r requirements.txt
     npm install
     cd frontend && npm install && cd ..

  3. Configure Environment Variables:
     Copy `.env.example` to `.env` and provide your `GROQ_API_KEY` and
     `PINECONE_API_KEY`.

  4. Run Both Servers Concurrently:
     npm run dev
     - Next.js Workspace:   http://localhost:3000
     - FastAPI Backend:     http://localhost:8000
     - Interactive Swagger: http://localhost:8000/docs

  5. Run Backend Independently:
     python app.py

  6. Run Frontend Independently:
     cd frontend
     npm run dev

  7. Run Automated Pytest Suite:
     python -m pytest

• Cloud Production Deployment:
  1. Backend Deployment on Render (`render.yaml`):
     - Link repository to Render as a Web Service.
     - Select Docker environment (or Python runtime with `pip install -r requirements.txt`).
     - Configure environment variables (`GROQ_API_KEY`, `PINECONE_API_KEY`,
       `DATABASE_URL`, `STORAGE_TYPE`, `FRONTEND_URL`).
     - Backend auto-provisions on port `$PORT`.

  2. Frontend Deployment on Vercel (`vercel.json`):
     - Import repository to Vercel.
     - Root install command: `npm install && cd frontend && npm install`
     - Build command: `cd frontend && npm run build`
     - Output directory: `frontend/.next`
     - Set environment variable: `NEXT_PUBLIC_API_URL=https://your-backend.onrender.com`
     - Deploy service.
